# LLM Todo 设计评审

一句诊断：方向是对的，但最大风险不是 UI，而是把长期人生规划误压成短期任务，导致系统看似勤奋、实际失真。

## 严重问题

- 长期规划必须和任务列表分层。人生、十年、年度页面不能自动拆成大量待办，否则系统会制造虚假确定性。
- 聊天写入必须有边界。首版可以自动新增任务和写日志，但不应在普通聊天里直接重写人生尺度页面。

## 主要问题

- 模型提供方适配不能内聚在 todo 业务里。需要让 `llm_agent_chat` 成为独立依赖，`llm_todo` 只提供上下文包和任务工具。
- 主界面必须直接显示任务、规划尺度和聊天窗口。不能做介绍页；用户打开后要立刻能问“今天下一步是什么”。
- 任务结构需要同时有时间尺度和领域，否则长期目标、项目和今天动作会混在一个队列里。

## 次要问题

- 需要补移动端下长任务标题和聊天长回复的滚动验证。
- 当前本地规则助手只能做简单意图识别，真实可用性依赖后续模型提供方接入和工具调用协议。

## 下一步

1. 先把新增任务、完成任务、列下一步做稳定。
2. 再接入 `llm_agent_chat` 的嵌入组件和模型提供方发现。
3. 最后做规划尺度页面写入审批和复盘工作流。
