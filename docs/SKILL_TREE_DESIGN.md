## 1. 核心理念

像游戏技能树一样：
- 每个**技能节点**有明确的等级（Lv.0 未解锁 → Lv.1 入门 → Lv.2 可用 → Lv.3 熟练 → Lv.4 精通 → Lv.5 大师）
- 技能之间有**前置依赖**（如"播客发布"依赖"音频后期"+"内容写作"）
- 点击某个技能能看到**详细能力清单**和**升级条件**
- 灰色 = 未解锁，蓝色 = 进行中，金色 = 已精通

**等级评估原则：保守优先。** 只在"稳定、可复现地达成"时才给对应等级。跑通一次不算，偶尔能用不算。

## 3. 等级定义（每个技能节点通用）

| 等级 | 名称 | 定义 | 标志 |
|------|------|------|------|
| Lv.0 | 🔒 未解锁 | 没有相关能力或工具，或工具从未成功使用 | 灰色 |
| Lv.1 | 🌱 入门 | 有工具/有Agent，偶尔能跑通，但产出不持续 | 浅蓝 |
| Lv.2 | 🔄 可用 | 能持续产出，但流程不稳定，经常需要人工干预 | 蓝色 |
| Lv.3 | ✅ 熟练 | 稳定产出，流程基本自动化，很少需要介入 | 绿色 |
| Lv.4 | ⭐ 精通 | 完全自动化闭环，异常才需要人 | 金色 |
| Lv.5 | 🏆 大师 | 见下方具体标准 | 紫色 |

### Lv.5 大师标准（具体化）

**技术型技能**（代码/工具/流程）：
- 代码/流程开源，有外部用户在用
- 或者被团队内部作为标准模板复用

**内容型技能**（写作/播客/视频）：
- 有稳定受众（如播客月活 > 1000，博客月阅读 > 5000）
- 或有明确变现（广告收入/付费内容）

**判断原则：Lv.5 不靠自己说，靠外部验证。**

### 升级条件示例（以"播客选题脚本"为例）

| 升级 | 条件 |
|------|------|
| Lv.0→1 | 有播客相关 Agent 并跑通过至少1次 |
| Lv.1→2 | 累计产出 ≥ 5 期选题脚本 |
| Lv.2→3 | 有固定选题流程，每周自动生成，持续 ≥ 4 周 |
| Lv.3→4 | 选题→脚本→录制→发布全闭环，无需人工干预 |
| Lv.4→5 | 播客有稳定听众（月活 > 1000），或有变现 |

## 4. KPI 面板（各线共用的结果指标）

> 注意：这不是一条技能线，是所有技能线的共同产出看板。

### 数据源
需要在各平台定期抓取：
- 粉丝数
- 文章阅读量
- 互动数据（点赞/评论/收藏）
- 收入数据

### 展示方式
在技能树页面顶部或侧边，显示全局 KPI 面板：
- 📊 粉丝数趋势（折线图）
- 📈 近7天/30天内容产出量
- 💰 收入（分投资/内容/工具）
- ⏱️ 时间投资回报率（各领域时间投入 vs 产出）

### 数据获取方式
- 微信公众号：通过公众号后台 API
- 知乎/CSDN/掘金等：Brave CDP 抓取
- B站：API
- GitHub：`gh` CLI
- 投资收益：已有基础

### 视觉风格
- 参考 RPG 游戏技能树（如暗黑破坏神、文明）
- 节点之间用连线表示依赖关系
- 灰色节点 = 未解锁（但可见，让人知道还有路可走）
- 解锁时有简单动画
- 顶部或侧边有 KPI 面板（粉丝/产出/收入趋势）

## 7. 优先级

### 最应该先补的技能（按战略价值排序）

| 顺序 | 技能 | 为什么 | 投入预估 |
|------|------|--------|----------|
| 🔴 1 | 写作→发布闭环到 Lv.3 | 这是一切内容的基础，现在发布不稳定，后面都卡在这 | 1-2周 |
| 🔴 2 | KPI 面板 + 数据采集 | 不知道现状就无法规划，先装仪表盘 | 1周 |
| 🔴 3 | 股票异常驱动模式 | 战略级验证——跑通"闭环自动化"范式，成功了复制到其他 agent | 1-2周 |
| 🟡 4 | 播客流程 | 等写作闭环稳定后再搞，文字素材复用 | 2-3周 |
| 🟢 5 | 时间投资回报率 | 你总说没时间，先搞清楚时间花在哪了 | 1周 |
| ⚪ 6 | 视频流程 | 最复杂，放最后 | 1个月+ |

### 实现顺序（给开发 agent 的）

**Phase 1：地基**
1. 后端数据模型：在现有 capabilities.json 基础上扩展 `level` / `dependencies` / `upgradeConditions` / `lastVerified`（上次验证日期）
2. 技能树可视化：树形布局 + 节点点击交互 + KPI 面板

**Phase 2：仪表盘**
3. KPI 数据采集 cron（各平台粉丝数、阅读量）
4. 时间投资回报率数据结构

**Phase 3：第一个闭环验证**
5. 股票异常驱动模式落地（异常检测 → 通知 → 记录结果 → 验证闭环）

**Phase 4：内容扩展**
6. 播客全流程
7. 视频流程（最复杂，单独迭代）

## 8. 实现约束

- 技能树等级数据存在 `capabilities.json` 或同类结构化文件中
- 每个节点字段：`id`, `name`, `level`, `maxLevel`, `parentId`, `dependencies[]`, `upgradeConditions[]`, `lastVerified`, `notes`
- KPI 数据单独存储，按时间序列
- 前端可以是 Web 页面（推荐，方便多端访问）或 CLI 工具
- 等级变更需要记录日志（谁改的、为什么、什么时间）
